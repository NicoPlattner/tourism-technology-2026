# AI Creative Director

Overview still opens a coherent saved image-caption pair instantly and makes no generation request on selector changes. The small Regenerate control now requests a complete creative from the existing `/api/marketing/generate-caption` endpoint using `generationMode: "creative"`. Caption-only callers remain compatible when the mode and creative-only fields are omitted.

The request adds travel period, arrival/departure dates and compact `candidateAssets` metadata to the existing audience, locale, age-based platform/tone/length and destination fields. It never sends image bytes or API credentials from the browser. Both OpenAI-compatible and n8n adapters reuse the same provider configuration, model, timeout, one-request behavior and structured-output validation. There is no second model call, agent framework or image generation.

`assetCatalog.json` is the shared, URL-free source of truth for the 16 library images. `assetCatalog.ts` filters the catalogue; `seasonalAssets.ts` resolves local browser URLs. Season is determined from the target arrival date, using calendar-season defaults December–February = winter, March–May = spring, June–August = summer, September–November = autumn. The exact age match is preferred. Compatible non-meme photographs from the same season and activity family can be alternatives (for example summer friends by a lake and a panoramic hiking trail). Cat creatives remain restricted to the meme direction. Some combinations have only one candidate; the model must then use it. Activities, visuals and platform are demo creative preferences, not measured demographic behavior.

The server reconstructs candidates from the trusted catalogue and rejects client-altered asset metadata, incorrect seasons, invalid dates and mismatched audience/platform combinations. The model returns exactly `assetId`, `caption`, `hashtags`, `language`, lowercase `platform` and a short `creativeReason`. Successful API responses additionally receive `source: "ai"` from the server. Validation enforces candidate membership, language, platform, length/hashtags and rationale shape. Conservative keyword checks reject obvious mismatches such as cats in a photographic landscape post or skiing in a summer scene. These checks cannot prove complete semantic correspondence; human review is still required, and the model may still return an invalid result. The OpenAI-compatible adapter makes one bounded correction attempt for complete invalid responses; a second invalid result is rejected and the previous post remains intact.

The client caches complete validated responses, including the selected asset ID and rationale, under normalized country/language/age/date/period/season/platform/tone and candidate metadata. Regenerate bypasses saved results but concurrent requests for the same creative key are deduplicated. Country, period and age changes isolate pending results. The preview derives the asset and caption from the same state object and updates both in one render. Pending or failed requests preserve the previous pair. Cached pairs return together on switching back. Local approvals include the asset ID, caption and hashtags, so a changed image also requires renewed review.

Existing pre-generated captions remain paired only with the exact visual metadata for which they were created. Other initial contexts use the existing clearly labelled coherent demo preview. No existing image files were regenerated or edited for this change. The n8n workflow template now forwards creative fields, but remains a template requiring credentials and activation; the direct compatible gateway is the configured live integration in this workspace.

Validation covers candidate filtering, tampered metadata, structured model requests, invalid asset/platform/language/visual combinations, API compatibility, complete-pair caching, alternate-image selection, pending/failure preservation, stale targeting changes, approvals and the existing dashboard flows. The project has no app lint command; type checking, unit/API tests, browser tests and production build are the available checks.

## Calendar travel dates

Overview now replaces the quarter dropdown with start/end date fields with a compact dashboard-styled calendar: white surfaces, red selected endpoints, a soft range highlight, and month/year controls. Dates default to 15–21 February 2027 and persist across country and audience changes. Only a complete valid range updates the campaign; missing or reversed dates leave the last valid campaign visible with an inline message. Cross-season ranges use the arrival date to select the visual season. Dates display as DD.MM.YYYY and accept that format or ISO dates when typed. The calendar supports arrow keys, Home/End, Page Up/Down, Escape, outside-click dismissal and automatic progression from start to end selection.

The campaign stores exact selected dates under user marketing preferences. The illustrative lead time is subtracted from the selected start date, publishing slots use the actual Europe/Vienna offset for each day, and the Creative Director receives `travelPeriod: "custom"` plus the exact dates. Campaign identities, creative cache keys and local approvals isolate each date range. Compatible saved seasonal captions remain instantly available when they match the same country, audience, platform and image metadata; changing dates never calls the LLM. Legacy preset identifiers remain supported by the mock-provider API and development fixtures, but are no longer offered in Overview.
