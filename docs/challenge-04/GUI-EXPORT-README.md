# Challenge 04 GUI data export

Precomputed tables for the front end: destination × origin of guests × time
frame → guests, nights, length of stay, daily distribution, booking lead time,
age profile. Generated by `models/export_gui.py` (branch `c04-data-models`).
Every value carries `is_estimate`, `method` and `grade`: no cell is empty.

## Files

| File | One row per | Key columns |
|---|---|---|
| `monthly_origin.csv` | destination × origin × month (2024-01 … 2027-12) | `guests`, `nights`, `nights_p10`, `nights_p90` (≥ 80 % range), `length_of_stay` (months with 0 guests: the pair's typical value), `is_estimate`, `method`, `grade` |
| `daily_share.csv` | origin × day (2024-01-01 … 2027-12-31) | `share_of_month` (sums to 1 within each month; always filled), `school_holiday_share` (0–1, share of the origin's population on school holiday; empty = no school calendar for that origin/year, then `is_estimate` = true and the share uses the destination pattern only), flags |
| `lead_time_by_arrival_month.csv` | arrival month (1–12) | `share_0d … share_180d` (booked 0–7, 8–30, 31–60, 61–89, 90–179, 180+ days ahead), `booked_at_least_Xd_ahead`, `median_days_ahead` |
| `lead_time_by_market_indicative.csv` | market group (DE, NL, BE_LU, NORDIC_UK, OTHER) | same shares, **indicative only** (grade C) |
| `age_profile.csv` | origin country × season (`winter`, `summer`); `ALL` = fallback | `age_0-5 … age_65+`, `median_age_band`, `share_children_0_14` |
| `origins.csv`, `destinations.csv` | lookups | codes, names, kind |
| `examples/*.json` | worked answers of `query()` | every field as `{value, is_estimate, method, grade, note}` |

Destinations: the 9 Austrian states (`W96-1` … `W96-9`, Tirol = `W96-7`) and
`PAZNAUN` (Paznaun-Ischgl). Origins: Statistik Austria codes (countries,
German regions `80`–`85` + `53`, Austrian states `01`, `70`–`77`), plus `DE`
(Germany total), `AT` (Austria total) and `DE-XX` (single German states).

## How to answer a GUI request

For destination D, origin O, time frame start … end:

1. Days in the frame: `daily_share` rows of O; nights per day =
   `share_of_month × nights` of (D, O, that month) from `monthly_origin`.
   Same for guests (use `guests`) and the range (`nights_p10`, `nights_p90`).
2. Sum over the days → guests, nights, range; length of stay = nights / guests.
3. Lead time: weight the arrival-month rows of `lead_time_by_arrival_month` by
   the nights per month; median days ahead → "book by" = start − median.
   Optional: the market group's indicative profile.
4. Age: row of O's country (see `origins.csv: calendar_country`) and season;
   none → `ALL`.
5. Flags of the answer = worst grade of the rows used; `is_estimate` if any
   row is an estimate. Show the `method` text as a hint.

## Grades and methods

| Grade | Meaning |
|---|---|
| A | observed (Statistik Austria) or model for a large origin (≥ 500k nights/year); model error ~10 % per month |
| B | model for a smaller origin; daily distribution with the origin's holidays; lead time for Tirol / Paznaun |
| C | estimate: 2-year average (small origins), carried forward after Sep 2027, German state = region split by population, Paznaun = Tirol × Paznaun share, lead time by market, proxy daily pattern, age profiles |
| D | rough fallback (age profile `ALL`) |

The daily pattern is Tirol's for every destination; for other states it is a
proxy (flag it in the UI). Lead time comes from Paznaun booking data (proxy for
other destinations). Age profiles come from guest cards of a comparable
Austrian ski region (Salzburger Sportwelt).
